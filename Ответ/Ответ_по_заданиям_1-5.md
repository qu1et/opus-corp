Общий механизм этапа (`scripts/01_clean.py`):

```python
def run_stage(code: str, label: str, predicate) -> list[tuple[str, str]]:
```

Лог пишется ровно в том формате, который предложен в ТЗ (`scripts/common.py`):

```python
def log_error(errors: list[tuple[str, str, str]], log_file: Path) -> None:
    """Лог отброшенных строк в формате ТЗ: ТИП / src / tgt."""
    with log_file.open("w", encoding="utf-8", newline="\n") as f:
        for typ, s, t in errors:
            f.write(f"{typ}\n{s}\n{t}\n")
```

## 1.1 Прочистка строк по длине (1–2 слова)

Правило ТЗ: если в одной из строк пары всего 1–2 слова, удаляется вся пара.
Реализация — порог `min_words = 3` (то есть отсекаются строки с 1–2 словами):

```python
def check_short(s: str, t: str) -> str | None:
    if len(s.split()) < args.min_words or len(t.split()) < args.min_words:
        return "SHORT"
    if args.max_chars and (len(s) > args.max_chars or len(t) > args.max_chars):
        return "MAX_CHARS"          # дополнительная защита от «простыней» (не по ТЗ)
```

## 1.2 Прочистка по разнице в длине

Правило ТЗ: если длина строк в символах отличается более чем в два раза, удаляются обе строки.
Формулировка «более чем в два раза» реализована как `ls >= 2·lt or lt >= 2·ls` (строгие
неравенства, чтобы ровно двукратное различие не вырезалось):

```python
def check_len_ratio(s: str, t: str) -> str | None:
    ls, lt = len(s), len(t)
    if ls == 0 or lt == 0:
        return "LEN_RATIO"
    if ls >= args.len_ratio * lt or lt >= args.len_ratio * ls:
        return "LEN_RATIO"
    return None
```

* удалено **2 312 пар**, осталось 558 127;
* лог: `logs/Tatoeba.en-ru_LEN_RATIO.log` (6 936 строк);
* прочищенный корпус после этапа: `data/steps/Tatoeba.en-ru.en_LEN_RATIO` +
  `data/steps/Tatoeba.en-ru.ru_LEN_RATIO` (по 558 127 строк).

Фрагмент лога:

```
LEN_RATIO
This is always the way it has been.
Так было всегда.
LEN_RATIO
This is always the way it has been.
Так всегда было.
```

Здесь видно типичный случай для пары en-ru: русская перевода короче английской больше чем
вдвое (в русском нет артиклей, больше свободная морфология), поэтому правило срабатывает и
на нормальных парах — объём удалений невелик (0.4%), оставляю правило как в ТЗ.

## 1.3 Прочистка по доле алфавитных символов

Правило ТЗ: если алфавитных символов меньше 80 %, удаляется пара. Используется
`.isalpha()`, как предложено в ТЗ:

```python
def alpha_ratio(text: str, ignore_space: bool, alphabet: set[str] | None = None,
                ignore_digits: bool = False) -> float:
    chars = [c for c in text if not (ignore_space and c.isspace())]
    if ignore_digits:
        chars = [c for c in chars if not c.isdigit()]
    if not chars:
        return 0.0
    if alphabet is not None:
        return sum(1 for c in chars if c in alphabet) / len(chars)
    return sum(1 for c in chars if c.isalpha()) / len(chars)
```

Пометка в логе говорит, на какой стороне просадка: `ALPHA_SRC`, `ALPHA_TGT`, `ALPHA_BOTH`.

* удалено **3 351 пара** (из них основная масса — `ALPHA_SRC`), осталось 554 776;
* лог: `logs/Tatoeba.en-ru_ALPHA.log` (10 053 строки);
* прочищенный корпус после этапа: `data/steps/Tatoeba.en-ru.en_ALPHA` +
  `data/steps/Tatoeba.en-ru.ru_ALPHA` (по 554 776 строк).

Фрагмент лога:

```
ALPHA_SRC
This will cost €30.
Это будет стоить 30 евро.
ALPHA_SRC
I make €100 a day.
Я зарабатываю сто евро в день.
```

**Изменение параметров по пункту «следуйте здравому смыслу».** Если считать долю алфавитных
символов по всем символам строки (вместе с пробелами и знаками препинания — ключ
`--all-chars`), то на английском тексте с нормальной пунктуацией доля всегда уходит ниже 80 %,
и в лог массово выписываются хорошие строки: на этом корпусе отсекалось **390 тысяч**
английских строк вместо 3.4 тысяч. Поэтому знаменатель по умолчанию считает только
непробельные символы (`alpha_ignore_space: true`). Второй вариант для случаев, когда в строке
много цифр: `--alpha-ignore-digits` (цифры исключаются из знаменателя).

Обработка кириллицы из ТЗ тоже реализована — ключ `--cyrillic-alpha`, множество символов
строится ровно так, как в методичке, плюс «ё»:

```python
CYRILLIC = {chr(c) for c in range(1040, 1104)} | {"ё"}
```

При `--cyrillic-alpha` для выходной строки считается доля именно кириллических букв, а не
просто `isalpha()` (иначе латинские имена собственные и «a» в русских строках считаются
алфавитными).

## 1.4 Прочистка с определением языка

Использована рекомендованная **fasttext-langdetect**
(`https://github.com/zafercavdar/fasttext-langdetect`, модель `lid.176.bin`, кэшируется в
`.cache/`). Входная строка должна определяться как `en`, выходная — как `ru`.

```python
def init_langdetect(low_memory: bool):
    cache = ROOT / ".cache"
    os.environ["FTLANG_CACHE"] = str(cache)
    ensure_lang_model(low_memory, cache)
    from ftlangdetect import detect

    def one(text: str) -> str:
        if not text.strip():
            return ""
        return detect(text=text, low_memory=low_memory)["lang"]

    return one

def check_lang(s: str, t: str) -> str | None:
    ls = detect_lang(s)
    lt = detect_lang(t)
    if ls != want_src and lt != want_tgt:
        return "LANG_BOTH"
    if ls != want_src:
        return f"LANG_SRC({ls})"      # в пометке виден определённый язык
    if lt != want_tgt:
        return f"LANG_TGT({lt})"
    return None
```

## 2.1 Получение скоров

```python
def encode(model, texts: list[str], batch_size: int, device: str, prompt: str = "") -> np.ndarray:
    """Эмбеддинги батчами; prompt дописывается к каждой строке (нужно для e5-моделей)."""
    if prompt:
        try:
            vecs = model.encode(texts, batch_size=batch_size, device=device,
                                show_progress_bar=True, prompt=prompt)
        except TypeError:
            vecs = model.encode([prompt + t for t in texts], batch_size=batch_size,
                                device=device, show_progress_bar=True)
    else:
        vecs = model.encode(texts, batch_size=batch_size, device=device, show_progress_bar=True)
    return np.asarray(vecs, dtype=np.float32)


def cosine_rows(a: np.ndarray, b: np.ndarray) -> np.ndarray:
    na = np.linalg.norm(a, axis=1)
    nb = np.linalg.norm(b, axis=1)
    return (a * b).sum(axis=1) / (na * nb)
```

Важная деталь e5: и вход, и перевод кодируются с одинаковым префиксом `query: `
(`prompt = "query: " if "e5" in args.model.lower() else ""`), иначе скоры несимметричны.

Формат выдачи с `-s` проверен на малой выборке (`scripts/check_score_format.py`): строка
выглядит так — сначала пары индексов, затем разделитель и скор логарифма правдоподобия:

```

0-0 1-1 2-2 ||| -3.79346
```

Парсер и сборка скора (`scripts/02_score_fastalign.py`):

```python
def parse_score(line: str) -> float | None:
    """Скор из строки с флагом -s: fast_align печатает «пары ||| скор»."""
    if " ||| " not in line:
        return None
    tail = line.rsplit(" ||| ", 1)[1].strip()
    try:
        return float(tail)
    except ValueError:
        return None

raw = (np.asarray(fwd) + np.asarray(rev)) / 2.0
tok = np.asarray([len(s.split()) + len(t.split()) for s, t in pairs], dtype=np.float32)
scores = np.asarray(raw / np.maximum(tok, 1.0), dtype=np.float32)
```

**Второе отступление «по здравому смыслу».** `alignment score` из `-s` — это суммарный
логарифм правдоподобия всей пары, он отрицательный и сильно зависит от длины предложения
(на корпусе: min = −1067.2, max = −3.6, mean = −21.6), поэтому одним числовым порогом для
коротких и длинных предложений не обойтись. Скор нормирован на число токенов пары:
`raw / (len_src + len_tgt)` (min = −4.60, max = −0.61, mean = −1.74, std = 0.39;
квантили 1/10/25/50/75/90/99 % = −2.86 / −2.26 / −1.97 / −1.69 / −1.46 / −1.28 / −1.01).
Порог из-за этого подбирается квантилями, а не фиксированными 0.3…0.9.

и склеенные в датасете не-переводы (см. 2.2). Основной метод для корпуса в 554 тысячи пар —

* **bicleaner / bicleaner-ai**: модели для пары en-ru есть

# 3. Обработка корпуса в SentencePiece

Скрипт: `scripts/03_spm.py`. Обучены **две** модели SPM: одна на входную часть (en), другая
на выходную (ru), затем обе части корпуса разбиты своими моделями.

```bat
python scripts\03_spm.py
```

Код обучения и применения:

```python
def train_side(input_file: Path, model_stem: Path, args) -> spm.SentencePieceProcessor:
    """SPM пишет <model_prefix>.model и <model_prefix>.vocab, поэтому передаём
    model_prefix (поля model в TrainerSpec нет)."""
    kwargs = {
        "input": str(input_file),
        "model_prefix": model_stem.as_posix(),
        "vocab_size": args.vocab_size,
        "model_type": args.model_type,
        "input_sentence_size": args.input_sentence_size,
        "shuffle_input_sentence": not args.no_shuffle,
        "hard_vocab_limit": args.hard_vocab_limit,
        "character_coverage": args.character_coverage,
    }
    if args.normalization_rule_file:
        kwargs["normalization_rule_file"] = str(args.normalization_rule_file)
    else:
        kwargs["normalization_rule_name"] = args.normalization
    spm.SentencePieceTrainer.train(**kwargs)
    model_file = Path(model_stem.as_posix() + ".model")
    return spm.SentencePieceProcessor(model_file=model_file.as_posix())


def tokenize(sp: spm.SentencePieceProcessor, lines: list[str], out_file: Path) -> None:
    """Записывает разбитые строки по одному предложению на строку."""
    with out_file.open("w", encoding="utf-8", newline="\n") as f:
        for line in lines:
            f.write(" ".join(sp.encode(line, out_type=str)) + "\n")
```

## 4.3 Сборка fast_align (установка)

Компиляция на Windows через MSYS2 MinGW (шаги README репозитория + специфика Windows),
`scripts/build_fast_align.sh`, вызов из `setup.ps1 -Tools`:

```bash
cd "$SRC/build"
rm -f CMakeCache.txt
cmake -G "MinGW Makefiles" -DCMAKE_POLICY_VERSION_MINIMUM=3.5 ..
cmake --build . -j 4

# MinGW-бинари требуют runtime-DLL; кладём их рядом, чтобы exe работал без MSYS2 в PATH.
for dll in libgcc_s_seh-1.dll libstdc++-6.dll libwinpthread-1.dll; do
  if [ -f "/mingw64/bin/$dll" ]; then cp "/mingw64/bin/$dll" "$SRC/build/"; fi
done
```

Нюансы сборки под Windows, с которыми пришлось разобраться: генератор `MinGW Makefiles`
требует установленный `mingw-w64-x86_64-make` (ставится через `pacman`), у CMake нужно
понизить минимальную версию `cmakelists.txt` флагом `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`,
а вне MSYS2 готовые `.exe` не стартуют без runtime-DLL (ошибка `0xC0000135`), поэтому DLL
копируются рядом с бинарями. Готовые бинари — `tools/fast_align/build/fast_align.exe` и
`tools/fast_align/build/atools.exe`; после этого они работают из обычного PowerShell, а
не только из MSYS2 (команды запуска — в 4.2).

Проверка `awesome-align` для «небольшого корпуса» не использовалась: корпус в 554 тысячи пар
не является небольшим, а на малой проверке (6 пар) выравнивание fast_align корректно.

```python
        raise SystemExit(
            "Аргументы: <число строк во входном корпусе> <нужное число строк> <файл> [файл…]\n"
            "Пример: python 05_get_rand_sample.py 554788 3000 "
            "data/scored/Tatoeba.en-ru.en data/scored/Tatoeba.en-ru.ru align/Tatoeba.en-ru.align"
        )
    total = int(positional[0])
    take = int(positional[1])
    files = [Path(p) for p in positional[2:]]
    return total, take, files, opts


def main(argv: list[str] | None = None) -> None:
    # sys.argv[0] — имя скрипта, позиционные аргументы идут с argv[1] (как в ТЗ).
    argv = sys.argv[1:] if argv is None else argv
    total, take, files, opts = parse_args(argv)

    if take > total:
        raise SystemExit(f"Запрошено {take} строк, а в корпусе заявлено {total}")

    contents: list[list[str]] = []
    for f in files:
        lines = f.read_text(encoding="utf-8").splitlines()
        if len(lines) != total:
            raise SystemExit(
                f"{f.name}: {len(lines)} строк, а ожидается {total} — параллельность нарушена"
            )
        contents.append(lines)

    rng = random.Random(opts.get("seed")) if opts.get("seed") is not None else random.Random()
    indexes = sorted(rng.sample(range(total), take))

    out_dir = Path(str(opts.get("out_dir"))) if opts.get("out_dir") else None
    written: list[Path] = []
    for f, lines in zip(files, contents):
        target = (out_dir / (f.name + ".rand")) if out_dir else f.with_name(f.name + ".rand")
        target.parent.mkdir(parents=True, exist_ok=True)
        with target.open("w", encoding="utf-8", newline="\n") as out:
            for i in indexes:
                out.write(lines[i] + "\n")
        written.append(target)
```

Ключевой момент сохранения параллельности: **одна и та же** выборка индексов
`random.sample(range(total), take)` применяется ко всем входным файлам, поэтому N-я строка
входного корпуса, её перевод и её выравнивание попадают в одну и ту же строку выборки.
Дополнительно (не по ТЗ, для проверяемости) выборка индексов сохраняется в
`rand/rand_indexes.txt` — в корпусе есть повторяющиеся строки, поэтому проверять
параллельность по содержимому ненадёжно, а по индексам — точно.

Команда запуска (итоговая тройка файлов после заданий 2–4, размер выборки 3000, seed 777):

# Отступления от буквальных формулировок ТЗ (по пункту «следуйте здравому смыслу»)

ТЗ прямо разрешает менять параметры, если иначе массово вырезаются хорошие строки. Все
отступления перечислены здесь, каждое сопровождается числом в логах:

| # | что в ТЗ буквально | что сделано и почему | где видно |
|---|---|---|---|
| 1 | доля алфавитных символов считается от строки целиком | знаменатель — непробельные символы (`alpha_ignore_space: true`); с пробелами порог 0.8 вырезал бы **390 000** корректных английских строк вместо 3 351 | `logs/Tatoeba.en-ru_ALPHA.log`, опция `--all-chars` |
| 2 | автоматический подбор порога скоринга | порог выставлен вручную (0.75): автоматика по целевой доле удалений срезала **66 738** хороших пар | `logs/Tatoeba.en-ru_02_review.txt`, `--auto --target-drop` |
| 3 | эмбеддинги `google/embeddinggemma-300m` | взята `intfloat/multilingual-e5-large` (MIT, без согласия и токена HF); модель из ТЗ включается опцией `--model` | `config.json`, `scripts/02_score.py --model` |
| 4 | `alignment score` из `fast_align -s` как число 0…1 | скор — это суммарный log-likelihood (отрицательный, зависит от длины), поэтому нормирован на число токенов пары и порог подобран процентилем | `scripts/02_score_fastalign.py`, `logs/Tatoeba.en-ru_02_fastalign_summary.txt` |
| 5 | в логе только «тип / вход / выход» | в тип добавлено число скора (`SCORE_LOW 0.7008`) и код определённого языка (`LANG_TGT(uk)`), чтобы лог был проверяем | все логи задания 1–2 |
| 6 | «удаление повторяющихся строк» не требовалось | дедупликация есть, но выключена по умолчанию (48 повторов), чтобы не удалять то, что ТЗ не просил удалять | опция `--dedup` (при включении пишет `logs/<tag>_DUP.log`) |

Ничего не удалялось «пачками» по правилам, которые режут хороший корпус: самый массовый
фильтр (`SHORT`, 29 444 пары) удаляет именно то, что требует удалять ТЗ (строки по 1–2 слова),
остальные правила дали от 733 до 3 351 удалений.

| `scripts/01_clean.py` | задание 1: 4 правила + логи |

| `scripts/03_spm.py` | задание 3: две модели SPM + разбивка |
| `scripts/04_align.py` | задание 4: формат `вход ||| выход`, fast_align forward/reverse, `atools grow-diag-final-and` |
| `scripts/05_get_rand_sample.py` | задание 5: случайная часть по `sys.argv` |
| `scripts/06_report.py` | сборка `report.md` из логов |
| `scripts/check_*.py` | проверки формата скоров, выравнивания и параллельности выборки |

Запуск:

```bat
python scripts\run_all.py                       # все этапы на текущем корпусе
python scripts\run_all.py --stages 1,2,3,4,5,6
python scripts\run_all.py --threshold 0.75      # явный порог скоринга
python scripts\run_all.py --score-method fastalign --percentile 5
python scripts\run_all.py --raw-src my.en --raw-tgt my.ru --name MyCorpus --src en --tgt ru
```
