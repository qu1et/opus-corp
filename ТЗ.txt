Практические задания на семестр. Всего их 5 штук, они достаточно простые, но требуют написания определённого объёма кода.
По каждому заданию пришлите мне выбранный текстовый корпус, результаты его обработки на каждом этапе, логи прочистки и собственно код.
Пожалуйста, следуйте здравому смыслу в своей работе. Если в лог прочистки массово выписываются хорошие строки, то параметры прочистки можно изменить, даже если у меня это не было указано.

Если вам это интересно, то для работы можно взять какой-нибудь свой (новый) корпус, а не готовый с OPUS. Когда я позднее поделюсь блокнотом для тюнинга модели под определённую тематику, можно будет опробовать там получившийся прочищенный корпус. Для данных с OPUS просто это будет не очень интересно, т.к. модели их уже видели. Но это я уже оценивать не буду.

1. Написать скрипт/пайплайн для прочистки параллельных корпусов
Нужно взять параллельный корпус с сайта OPUS:
https://opus.nlpl.eu/
Вы вольны сами выбрать языковое направление и конкретный корпус. Корпус объёмом в десятки миллионов строк лучше не брать из экономии времени и ресурсов. Оптимальным будет что-то около 100-500 тысяч строк.

Нужно прочистить этот корпус по следующим четырём пунктам, не нарушая параллельности:
1. Метод для прочистки строк по длине. Если в параллельном корпусе одна из строк состоит лишь из 1-2 слов, то эту строку (и соответствующую параллельную) следует удалить. Удалённые строки выписать в лог.

2. Метод для прочистки строк по разнице в длине. Если разница между длиной строк в символах более чем в два раза, то обе строки нужно удалить. Удалённые строки выписать в лог.

3. Метод для прочистки строк по наличию алфавитных символов. Если в строке их меньше 80%, то эту строку (и соответствующую параллельную) следует удалить. Удалённые строки выписать в лог.
У строки в Python есть полезный метод .isalpha(), который здесь пригодится.
Если вы хотите отдельно обработать, скажем, только кириллические строки, то нужно получить список кириллических символов:
cyr_al = set()

for c in range(1040, 1104):
  cyr_al.add(chr(c))
4. Прочистить корпус с использованием библиотеки для определения языка.
Я рекомендую использовать fasttext-langdetect:
https://github.com/zafercavdar/fasttext-langdetect
Он работает достаточно точно и очень быстро.
Если у вас корпус en<>ru, то нужно из входной части удалить строки, которые будут определены не как en, а из выходной строки удалить строки, которые определены не как ru. Эти строки записать в лог.

На выходе у вас должны быть:
- прочищенный корпус (два параллельных текстовых файла)
- лог, куда с соответствующими пометами выписаны отброшенные строки

Для лога можно использовать такой формат:
<ТИП_ОШИБКИ>
<строка_на_входном_языке>
<строка_на_выходном_языке>

2. Прочистить корпус с использованием инструментов для скоринга
Получить оценку параллельности сегментов одним из доступных инструментов, проанализировать выдачу (отсортировать корпус по скорам, выделить, по какому порогу проходит граница качества параллельности) и прочистить корпус. Удалённую часть сохранить в лог с указанием скоров.
Доступные инструменты:
- fast-align
https://github.com/clab/fast_align
Если к стандартной команде получения выравнивания добавить флаг -s, то вместе с выравниванием будет получен т.н. alignment score, который можно использовать для оценки параллельности:
./fast_align -i text.fr-en -d -o -v -s > forward.align
Этот метод не подходит для корпусов малого объёма (качество будет плохим) + является требовательным к оперативной памяти.

- bicleaner
- bicleaner-ai
См. блокнот:
https://colab.research.google.com/drive/1rdUuBl2ZnigA929PFi31iqxRHeZR3NhK?usp=sharing
Требуются специальные модели. Доступные модели смотреть здесь:
https://github.com/bitextor/bicleaner-data/releases/tag/v1.6
https://huggingface.co/bitextor/models
- COMET
Требуется модель cometkiwi-da
https://huggingface.co/Unbabel/wmt22-cometkiwi-da
Она же для запуска через pymarian:
https://huggingface.co/Unbabel/wmt22-cometkiwi-da-marian
Нужно согласиться с лицензией и перед запуском оценки авторизоваться в huggingface-hub.
Данная модель может выполнять оценку перевода без эталона. По запуску COMET позднее (на паре про метрики) будет отдельный блокнот, на который можно будет ориентироваться.

- marian-scorer
Блокнот с примером:
https://colab.research.google.com/drive/1D8p9s-SzdkJOiBgzjRlIe-wWMEpStM69?usp=sharing
Требуются модели перевода для данной языковой пары. Открытые модели в формате marian можно взять с репозитория OPUS-MT. Например, модели для арабско-русского направления:
https://object.pouta.csc.fi/Tatoeba-MT-models/ara-rus/opus-2020-07-03.zip
https://object.pouta.csc.fi/Tatoeba-MT-models/rus-ara/opus-2020-07-03.zip
Оценка тогда выполняется в двух направлениях, а в качестве финального скора берётся среднее из двух значений.

- Мультиязычные эмбеддинги
Можно в качестве скора использовать косинусное сходство между векторами входного предложения и его перевода, если для обоих получить эмбеддинги одной мультиязычной моделью. Например, embeddinggemma:
https://huggingface.co/google/embeddinggemma-300m
Тогда достаточно получить для каждой пары вектора, подсчитать на них сходство, и это и будет скором в данном случае.

3. Обработать получившийся корпус в SentencePiece
https://github.com/google/sentencepiece
Обучить две модели spm: одну на входной части корпуса, другую - выходной.
Затем разбить эти корпуса при помощи получившихся моделей.
См. документацию на Github:
https://github.com/google/sentencepiece?tab=readme-ov-file#train-sentencepiece-model

4. На получившемся корпусе получить файл выравнивания
Рекомендую использовать fast-align:
https://github.com/clab/fast_align
Установка fast_align требует компиляции, но все шаги прописаны в ридми на Github.
Само выравнивание получается тремя командами:
./fast_align -i text.fr-en -d -o -v > forward.align
./fast_align -i text.fr-en -d -o -v -r > reverse.align
./atools -i forward.align -j reverse.align -c grow-diag-final-and
Если ваш корпус небольшой, можно использовать awesome-align:
https://github.com/neulab/awesome-align

Оба инструмента требуют особого формата входных данных (об этом есть в ридми у обоих):
%вход% ||| %выход%
Получить такой формат можно через код в Python. Либо, если корпус сохранён в виде пары файлов, такой командой в Colab:
!paste file1 file2 | sed 's/ *\t */ ||| /g' > file_out
Где file1 и file2 нужно заменить на названия файлов вашего корпуса, а file_out - на название выходного файла.
Команда paste склеивает два файла в один с разделителем в виде табуляции (/t), а команда sed заменяет табуляцию на |||.

5. Выделить из итоговой тройки файлов "тестовую" часть
Нужно написать скрипт (т.е. файл .py), который выделяет из группы файлов случайную часть, не нарушая параллельности.
Он принимает на вход следующие аргументы:
- число строк во входном корпусе
- необходимое количество строк в случайной части
- собственно корпуса, которые требуется обработать (от 1 до бесконечности)

Для обработки аргументов здесь проще всего использовать sys.argv. Это массив позиционных аргументов, с которым был запущен скрипт. И вы вольны обращаться к любому элементу этого массива: sys.argv[1], sys.argv[-1], sys.argv[1:3].
Для собственно выборки предлагаю использовать библиотеку random, а именно метод sample, который позволяет сделать выборку заданного размера на каком-либо объекте.

Пример запуска такого скрипта:
!python get_rand_sample.py 1067840 3000 Tanzil.en-ru.en Tanzil.en-ru.ru Tanzil.en-ru.align
На выходе скрипт должен создать файлы: Tanzil.en-ru.en.rand, Tanzil.en-ru.ru.rand, Tanzil.en-ru.align.rand.
